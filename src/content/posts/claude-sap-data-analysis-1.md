"90일 넘은 매출채권이 많은 거래처가 어디지?" SAP를 쓰는 회사에서 이런 질문이 생기면 보통 보고서를 찾거나, 담당자에게 추출을 부탁하거나, 엑셀을 엽니다. 답은 ERP 안에 다 있는데 꺼내는 데 시간이 걸립니다.

이 질문을 클로드(Claude)에게 바로 할 수 있다면 어떨까요. 저는 S/4HANA 테스트 환경을 클로드에 연결해 판매·구매·재고·채권·채무·운전자본 데이터를 말로 물어보는 구성을 직접 만들어 봤습니다. 이 글은 그중 **연결하고 첫 질문을 던지기까지**를 정리한 것입니다. 테스트 환경이라 답으로 나온 숫자는 싣지 않고, 어떻게 묻고 무엇이 돌아왔는지만 적었습니다.

## 클로드가 SAP 데이터를 읽는 방식 — 커넥터와 MCP

클로드는 혼자서 회사 ERP를 들여다볼 수 없습니다. 길을 놓아 줘야 합니다. 그 길이 **MCP**(Model Context Protocol)입니다. AI가 외부 시스템의 기능을 "도구"로 불러 쓰게 하는 공개 표준이고, 클로드에서는 이것을 **커넥터**라는 이름으로 붙입니다.

2026년 11월 기준으로 claude.ai와 클로드 데스크톱에서는 원격 MCP 서버를 사용자 지정 커넥터로 추가할 수 있습니다. 무료 요금제는 사용자 지정 커넥터를 1개까지 쓸 수 있고, Pro·Max는 본인이 직접 추가합니다. 팀·엔터프라이즈 요금제에서는 관리자가 조직에 추가하고, 구성원이 각자 연결해 켜는 방식입니다.

![클로드가 SAP 데이터를 읽는 길](/img/d01-1_claude_sap_architecture.png)

구조는 네 칸입니다. 클로드가 커넥터로 **MCP 서버**를 부르고, MCP 서버가 S/4HANA의 **CDS 뷰**를 OData로 읽습니다. 여기서 가장 중요한 것은 역할 나누기입니다.

- **클로드**는 질문을 이해하고, 어떤 도구를 부를지 고르고, 결과를 해석해 설명합니다.
- **MCP 서버**는 어떤 데이터를 어떤 단위로 줄지 정합니다. 집계는 여기서 합니다.
- **S/4HANA**는 누가 무엇을 볼 수 있는지 판단합니다. 권한은 여기서 걸립니다.

이 셋이 섞이면 문제가 생깁니다. 뒤에서 실제로 겪은 예를 적었습니다.

## 연결까지 — 네 단계

**1. 데이터 고르기.** 처음부터 전부 붙이지 않았습니다. 분석용 CDS 뷰 가운데 질문이 가장 많이 나오는 영역 한두 개(운전자본, 매출채권)부터 시작했고, 익숙해진 뒤 판매·구매·재고·채무까지 여섯 영역으로 넓혔습니다.

**2. MCP 서버 만들기.** 도구는 테이블 단위가 아니라 **질문 단위**로 만들었습니다. "운전자본 조회", "채권 연령 분석", "구매처 집중도"처럼요. 도구마다 받는 조건(회사, 기간, 거래처 등)을 분명히 적어 두면, 클로드가 어떤 도구를 언제 써야 하는지 훨씬 정확하게 고릅니다.

**3. 배포하고 로그인 붙이기.** 서버는 SAP BTP에 올렸고, 클로드가 접속할 때 사용자가 로그인하도록 OAuth를 붙였습니다. 커넥터는 공개 인터넷에서 닿는 주소여야 합니다. 여기서 시간을 가장 많이 썼습니다.
- 클로드는 MCP 서버에 붙을 때 표준 경로에서 인증 서버 정보를 찾는데, 인증 서비스가 그 경로에 응답하지 않아 연결이 멈췄습니다. MCP 서버가 인증 서버 정보를 대신 알려 주도록 바꿔 해결했습니다.
- 로그인 화면에서 고를 수 있는 로그인 경로가 여러 개였는데, ERP와 신뢰가 맺어진 경로로 로그인해야만 내 권한으로 조회가 됐습니다.
- 로그인 토큰은 한 시간 정도면 만료됩니다. 갱신 토큰을 켜 두지 않으면 대화 도중에 갑자기 조회가 실패합니다.

**4. 커넥터 추가하고 켜기.** 클로드의 **사용자 지정(Customize) › 커넥터** 메뉴에서 서버 주소를 넣고, 대화창에서 그 커넥터를 켜면 준비가 끝납니다.

## 첫 질문 다섯 개 — 이렇게 물었다

연결하고 나서 실제로 던진 첫 질문들입니다.

| 질문 | 클로드가 한 일 | 눈여겨본 점 |
|---|---|---|
| "이번 달 운전자본 현황을 회사별로 보여 줘" | 운전자본 도구를 한 번 부르고 표로 정리 | 내 권한에 있는 회사만 나옴 |
| "90일 넘은 매출채권이 많은 거래처 상위 10곳" | 채권 연령 도구로 구간별 금액을 받아 순위를 매김 | 거래처명은 정책에 따라 가려져 나옴 |
| "재고 회전이 느린 자재군은?" | 재고 도구 결과로 회전을 계산하고 기준을 설명 | 계산 방식을 먼저 밝히고 답함 |
| "구매처 한 곳에 몰린 자재가 있나?" | 구매 도구로 공급사별 비중을 보고 집중된 자재를 골라냄 | "왜 위험한가"까지 해석을 붙임 |
| "월말 마감 전에 확인할 이상 징후를 찾아 줘" | 채권·채무·재고 도구를 차례로 불러 점검 목록으로 정리 | 도구 여러 개를 스스로 엮음 |

처음 몇 번은 같은 질문을 기존 보고서와 나란히 놓고 숫자를 대조했습니다. AI가 맞게 답하는지 확인하는 단계를 건너뛰면 나중에 아무도 결과를 믿지 않습니다.

## 잘 되는 질문, 안 되는 질문

**잘 되는 질문**은 도구가 이미 집계해서 돌려주는 질문, 그리고 그 결과를 비교·해석하는 질문입니다. "지난달보다 왜 늘었는지 후보를 짚어 줘" 같은 질문에서 클로드가 가장 쓸모 있었습니다.

**안 되는 질문**은 원시 데이터를 잔뜩 받아 클로드에게 합계를 맡기는 질문입니다. 초기 도구 가운데 하나는 집계 없이 전표 행을 그대로 돌려줬는데, 행이 많아지자 계산이 흔들리고 답이 느려졌습니다. 서버에서 먼저 묶어 주는 집계 도구를 붙이자 응답 크기가 크게 줄고 답도 안정됐습니다. **집계는 서버가, 해석은 클로드가** 하는 것이 원칙입니다.

또 하나는 **기본값의 함정**입니다. 회사나 기간을 말하지 않으면 서버 설정에 적힌 기본값으로 조용히 조회하는 도구가 있었습니다. 사용자는 전체를 물었다고 생각하는데 실제로는 일부만 본 셈입니다. 그래서 응답에 "실제로 적용된 범위"를 함께 돌려주도록 고쳤고, 클로드도 답할 때 그 범위를 먼저 말하게 됐습니다.

## 꼭 지킬 것 세 가지

1. **내 권한만큼만 보이게.** 연결 계정 하나에 넓은 권한을 주면 누가 물어도 같은 범위가 보입니다. 로그인한 사람의 신원이 ERP까지 이어져야 권한이 지켜집니다. 자세한 내용은 [AI가 ERP를 조회할 때, 사용자 권한은 어떻게 지켜질까?](https://blog.aspn.co.kr/ai-agent-erp-user-authorization)에 정리했습니다.
2. **집계는 서버에서.** 클로드에게 계산을 떠넘기지 않습니다.
3. **가릴 것은 가리고, 기록은 남기기.** 거래처명 같은 식별자는 정책에 따라 가리고, 누가 어떤 도구로 무엇을 조회했는지 남깁니다. 운영에서 필요한 일은 [AI PoC는 성공했는데, 왜 운영 단계에서 막힐까?](https://blog.aspn.co.kr/mcp-server-operations-credentials-audit-masking)에서 다뤘습니다.

## 2026년 11월 기준, SAP 쪽 흐름

SAP도 같은 방향으로 움직이고 있습니다. SAP는 2025년 11월 TechEd에서 MCP 지원 확대를 발표했고, 2026년 Sapphire에서는 Anthropic과의 파트너십을 발표해 클로드를 SAP Business AI 플랫폼과 Joule의 확장으로 가져오겠다고 밝혔습니다. 다만 발표 당시 이 통합은 계획으로 소개되었으니, 실제로 어떤 기능이 언제 제공되는지는 SAP 공지를 직접 확인하는 것이 좋습니다.

그래서 당분간은 두 길이 함께 갈 것으로 봅니다. SAP가 제공하는 표준 경로가 넓어지는 동안, 이 글처럼 필요한 CDS 뷰를 직접 MCP 서버로 감싸 클로드에 붙이는 방법도 계속 쓸모가 있습니다.

## 시작 전 체크리스트

- [ ] 클로드에게 물어보고 싶은 질문 10개를 먼저 적었는가
- [ ] 그 질문에 답할 CDS 뷰(분석용)가 있는가
- [ ] 도구를 테이블이 아니라 질문 단위로 설계했는가
- [ ] 도구가 원시 행이 아니라 집계 결과를 돌려주는가
- [ ] 로그인한 사용자의 권한으로 조회되는가 (권한이 다른 두 사용자로 시험)
- [ ] 로그인 토큰 갱신이 켜져 있는가
- [ ] 응답에 실제 적용된 범위(회사·기간)가 함께 나오는가
- [ ] 처음 몇 주는 기존 보고서와 숫자를 대조하는가

시리즈 다음 글에서는 이번에 짧게 넘어간 2단계, **SAP용 MCP 서버를 직접 만들 때 알아야 할 것**을 다룹니다.
